This final project in course CPE212 helped me understand more how ansible and docker works. Through Docker, I learned how containerization ensures consistent application deployment across different operating systems. Meanwhile, using Ansible improved my understanding of automation through playbooks, inventory files, YAML syntax, and conditional tasks. Although I encountered challenges such as connection errors, permission issues, and configuration mistakes, troubleshooting these problems strengthened my technical and problem-solving skills. I also recognized the importance of teamwork, communication, and proper task distribution throughout the project. This final project helped us understand how Docker and Ansible contribute to efficient, consistent, and reliable server management in real-world environments/experiences.
This class on automating server management has been very helpful in introducing me to large-scale automation of configuration through the use of Ansible, and large-scale deployment through the use of Docker. I've learned a lot from installing specific software onto different OS distributions using Ansible to deploying containerized applications with the use of Dockerfile and Docker Compose. It was very fun learning about the different enterprise monitoring tools such as Prometheus and NagiOS and despite the trouble I initially had with setting up their installation in Ansible, it was still very interesting how enterprises can automate these tasks. I've also developed my skill in reading through different documentations so as to learn how to install or even what parameters different functions and modules take to run different commands. Overall, this course has been both very entertaining and satisfying moving up from bash scripts and linux commands in my previous system administration course.
Working on this final project significantly broadened my practical understanding of containerization and system automation. Through Docker, I saw firsthand how packaging an application into containers solves environment inconsistencies across different operating systems. Managing Ansible enhanced my ability to structure automated workflows using playbooks, inventory configurations, YAML syntax, and conditional execution paths. Dealing with real-world setup hurdles, like SSH authentication errors, privilege management, and configuration syntax bugs, greatly improved my debugging and troubleshooting approach. Beyond the technical aspect, the project emphasized the value of clear team communication, structured delegation, and collaborative effort. Ultimately, this experience demonstrated how combining containerization with automated configuration leads to consistent, reliable, and scalable server management in real-world infrastructure.
